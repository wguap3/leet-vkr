# Stackr Java

Платформа алгоритмической подготовки и соревнований на Java. Участник решает задачи в браузере; организатор управляет задачами, тестами и контестами.

## Локальный запуск

Нужны работающий Docker Engine / Docker Desktop с Compose и `openssl`. JDK, Maven, Node.js и PostgreSQL на хосте для запуска через Compose не нужны. Первый запуск скачивает зависимости и образы из интернета.

```bash
bash scripts/dev.sh
```

Открыть [http://localhost:3100](http://localhost:3100). API для диагностики: [http://localhost:8080/api/tags](http://localhost:8080/api/tags).

Скрипт один раз создаёт `.env` со случайными паролем PostgreSQL и ключом JWT. При повторном запуске он сохраняет настройки и данные. Порты можно изменить в `.env`: `WEB_PORT`, `API_PORT`. Если порт занят, используйте свободный; другие контейнеры останавливать не нужно. Изменение пароля в `.env` не меняет пароль уже созданной базы данных.

```bash
docker compose ps
docker compose logs -f api runner
docker compose stop
docker compose start
```

`stop` и `start` сохраняют базу. Для применения изменений кода снова запустите `scripts/dev.sh`. Не используйте `down -v` для обычной остановки: он удаляет данные.

## Первый сценарий

1. Зарегистрировать пользователя с ролью организатора.
2. Создать задачу, добавить публичные примеры и скрытые тесты, опубликовать её.
3. Выйти и зарегистрировать участника.
4. Открыть задачу, написать Java-программу с `public class Solution` и `public static void main(String[] args)`.
5. Проверить программу на своём вводе, отправить на проверку и открыть историю посылок.
6. Для соревнования создать контест, указать задачи и интервал, зарегистрировать участника и открывать задачу именно из контеста. Контекст контеста передаётся в посылку.

Готовых учётных записей и общего пароля администратора новый запуск не создаёт. Роль ADMIN не назначается через регистрацию. Старый `seed.sh` относится к первоначальной дипломной сборке и не является текущим способом запуска; для проверки используйте сценарий ниже.

## Автоматические проверки

Для локальной разработки нужны JDK 21, Maven, Node.js 22+ и npm.

```bash
mvn test
mvn -f runner/pom.xml test
cd web
npm ci
npm run build
```

Тесты API используют H2 и подменённый RunnerClient. Проверка Liquibase на H2 подтверждает применение changelog; это не эквивалент PostgreSQL и полной проверки приложения.

Проверка настоящих sandbox-контейнеров:

```bash
docker pull eclipse-temurin:21-jdk-alpine
STACKR_DOCKER_TESTS=true mvn -f runner/pom.xml test
```

После запуска всего приложения:

```bash
python3 scripts/smoke.py
# При другом порте:
STACKR_URL=http://localhost:3101 python3 scripts/smoke.py
```

Сценарий создаёт отдельных пользователей и задачу, проверяет через HTTP AC, WA, CE, RE, TLE и историю посылок. Он намеренно оставляет демонстрационные записи для осмотра. Это не браузерный тест всех экранов.

## Архитектура и ограничения

- `src/`: Spring Boot 3.2.5, Java 21, Spring Security/JWT, JPA, PostgreSQL, Liquibase.
- `runner/`: доверенный сервис управления Docker; каждое выполнение и компиляция используют отдельный ограниченный контейнер.
- `web/`: React 18, TypeScript, Vite, Monaco; production-сборка обслуживается nginx с проксированием `/api`.
- Очередь: записи `PENDING` в PostgreSQL, один плановый обработчик с блокировкой выбранной записи. Неисполненные задания остаются в БД после перезапуска. Это локальная конфигурация с одним экземпляром API; масштабирование требует отдельной проверки.
- Редактор и worker обслуживаются локально, без загрузки Monaco из CDN.
- Таблица соревнования обновляется запросом каждые пять секунд.
- Память решения сейчас не измеряется: API возвращает `null`. Время — стенное время запуска, включая накладные расходы Docker, а не точное CPU-время.
- Вердикт `ERROR` означает сбой инфраструктуры проверки, не ошибку участника.
- HTTP-вызов runner имеет конечный таймаут; большие наборы медленных тестов требуют согласования общего бюджета проверки.

Runner имеет доступ к Docker socket. Его порт не публикуется на хост, сокет не попадает в контейнеры решений. Перед размещением в интернете нужен отдельный проект изоляции runner, ограничения запросов и проверка нагрузки. Текущая поставка предназначена для локальной разработки и приёмки.
