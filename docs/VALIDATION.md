## Проверенная изоляция

Реальные Docker-тесты проверили принятие корректного решения, неверный ответ, ошибку компиляции, ошибку выполнения, остановку бесконечного цикла, остановку вывода свыше лимита, запрет записи в том с классами и отсутствие Docker socket внутри решения. Дополнительно тест конфигурации проверяет параметры ограниченного контейнера. Это не полный аудит устойчивости sandbox к враждебному коду.

## Важные наблюдения

- Docker Desktop первоначально не был запущен. После запуска пользователем сервер Docker 28.1.1 стал доступен.
- Первая попытка Docker-теста началась до завершения загрузки образа и превысила таймаут операции; после полной загрузки образа все восемь контейнерных сценариев прошли. Инструкция явно требует подготовленный образ.
- В среде Codex buildx не мог записывать служебные данные в стандартный каталог; при проверке использован BUILDX_CONFIG внутри рабочей папки. Конфигурация пользователя в ~/.docker не изменялась.
- Первый HTTP smoke обнаружил реальный дефект: тест с пустым вводом отклонялся как невалидный. API и формы скорректированы; повторная проверка с пустым вводом прошла.
- Порт 3000 занят существующей Gitea пользователя; Stackr использует 3100. Сторонние контейнеры не изменялись и не останавливались.
- Новый стек проверялся на новом собственном томе `stackr-local_postgres_data`; существующие сторонние данные не удалялись. Повторный запуск сохраняет локальную БД.
- После запуска сохранены отдельные демонстрационные пользователи, задачи и посылки smoke-проверок. Их пароли генерировались случайно; фиксированный общий администратор не создавался.

## Что ещё нельзя считать проверенным

Полный дизайн и доступность экранов, мобильная компоновка, все браузерные сценарии ролей, нагрузка, долгие наборы тестов, аварийное завершение самого runner, эксплуатационное резервное копирование и внешняя публикация. Миграционный тест на H2 отдельно не считается доказательством PostgreSQL; запуск настоящего PostgreSQL подтверждён Compose и HTTP-сценарием выше.
