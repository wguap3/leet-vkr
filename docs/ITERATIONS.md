## 3 ноября 2026 — восстановление после остановки сервисов

Воспроизведено: при остановленном runner DNS окружения выдавал 240.0.0.44 вместо адреса Compose; Java сохраняла этот ответ и продолжала получать EOF после запуска runner. Проверка отдельным Java-процессом показала сохранение неправильного адреса на протяжении всех 12 замеров. Прямые HTTP-запросы к уже работающему runner успешно возвращали AC.

Исправлено: TTL успешного и отрицательного DNS-ответа Java установлен в 1 секунду, использование устаревшего ответа отключено. Для внутреннего имени runner добавлена проверка адреса перед запросом. Nginx также обновляет адрес API через Docker DNS вместо сохранения адреса на весь срок работы процесса.

Проверено на реальном Compose:
- остановка runner → ERROR, рейтинг не изменился;
- запуск runner без перезапуска API → пять TLE и последующий AC;
- шесть одновременных отправок → пять приняты, одна отклонена лимитом;
- пересоздание API без перезапуска web → HTTP API доступен через nginx;
- 95 серверных тестов прошли без ошибок и пропусков.

Настройки сверены с [документацией Java 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/net/doc-files/net-properties.html) и [документацией nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass). Это проверка конкретных отказов, а не полный нагрузочный или security-аудит.

Финальная браузерная проверка этапа: 3 сценария прошли — приглашение с регистрацией и заменой ссылки, Java-редактор с пользовательским вводом/черновиком/реальным AC, главная и вход без JavaScript-ошибок.
